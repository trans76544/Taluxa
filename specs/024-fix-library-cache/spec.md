# Feature Specification: 电影列表返回与缩略图缓存复用

**Feature Branch**: `codex/024-fix-library-cache`

**Created**: 2026-10-06

**Status**: Draft（根据已完成的缓存修复补写）

**Input**: User description: "现有界面的缓存策略有问题，特别是点进某一个电影后，点击返回所有电影界面，又要重新进行一次缩略图的加载。将上面的修改生成对应的 spec。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 返回电影列表时立即继续浏览 (Priority: P1)

作为浏览电影的用户，我进入某部电影的详情后返回，希望立即看到刚才的电影列表和已加载海报，不必再次等待整页加载。

**Why this priority**: 这是用户报告的主要问题，反复进入详情是浏览电影时的常见操作。

**Independent Test**: 首次打开电影列表并等待海报加载完成，进入电影详情，再在列表刷新被人为延迟的情况下返回，检查列表和海报是否立即可见。

**Acceptance Scenarios**:

1. **Given** 数据缓存和图片缓存已启用，当前列表和海报已成功加载且缓存仍有效，**When** 用户进入电影详情后返回同一列表，**Then** 第一帧列表内容即展示已有电影和海报，不出现整页列表加载提示，也不重新从服务器下载这些海报。
2. **Given** 返回时已展示已有列表，**When** 后台刷新仍未完成，**Then** 列表保持可见，用户可以继续点击电影并打开详情。
3. **Given** 返回后服务器提供的电影及海报内容没有变化，**When** 后台刷新完成，**Then** 已显示的海报不被清空，不再次经历加载过程。
4. **Given** 返回后服务器提供了新增、删除或修改的电影，**When** 后台刷新成功，**Then** 列表更新为新的结果，仅内容发生变化的图片需要加载。

---

### User Story 2 - 通过本地缓存加载海报 (Priority: P1)

作为浏览电影的用户，我希望应用优先使用本地海报，避免同一张海报先从服务器加载、随后又切换到本地图片。

**Why this priority**: 图片重复加载会造成额外等待和流量消耗，即使已有磁盘缓存也会损害浏览体验。

**Independent Test**: 在本地缓存处理被延迟的情况下首次展示海报，再同时展示多个引用同一海报的卡片，并重复进入相同页面，检查图片来源和下载次数。

**Acceptance Scenarios**:

1. **Given** 图片缓存可用，但海报是否已缓存尚未确定，**When** 卡片首次展示，**Then** 应用先完成本地缓存处理，再展示确定的图片，不提前发起额外的服务器图片加载。
2. **Given** 同一图片的本地地址已成功获取且仍有效，**When** 用户再次打开引用这张图片的卡片，**Then** 卡片立即复用本地地址，无须再次等待缓存处理。
3. **Given** 多张卡片同时引用同一张尚未完成加载的图片，**When** 应用处理这些图片，**Then** 卡片共享该次处理结果，不重复下载同一图片。
4. **Given** 卡片改为展示另一张图片，**When** 新图片尚未加载完成，**Then** 卡片不得暂时显示上一张图片作为新内容。

---

### User Story 3 - 刷新失败时仍可浏览已有内容 (Priority: P2)

作为网络不稳定时的用户，我希望返回列表后的刷新失败不会使刚才已加载的电影和海报消失。

**Why this priority**: 缓存复用不仅应改善正常网络下的速度，也应保留网络异常时仍可使用的浏览内容。

**Independent Test**: 成功加载列表后进入详情，再使返回时的刷新失败，检查列表保留及提示；另在没有缓存的情况下使首次加载失败，检查错误提示。

**Acceptance Scenarios**:

1. **Given** 当前列表存在有效缓存，**When** 返回后的后台刷新失败，**Then** 已有列表保持可见，并提示当前展示的是保存内容。
2. **Given** 当前列表没有可复用的缓存，**When** 首次请求失败，**Then** 应用展示加载失败提示，不展示其他列表的缓存内容。
3. **Given** 图片缓存处理失败或返回服务器图片地址，**When** 当前图片仍可从服务器加载，**Then** 应用允许使用服务器图片；再次访问时应重新尝试本地缓存处理，而不是将这次回退永久视为有效本地缓存。

---

### User Story 4 - 缓存与当前浏览身份和设置一致 (Priority: P2)

作为使用多个服务器、账号或排序方式的用户，我希望缓存对应当前浏览上下文，并且清理缓存或调整缓存设置后能生效。

**Why this priority**: 缓存必须避免混淆账号内容、媒体库和排序结果，也不能使用户的缓存管理操作失效。

**Independent Test**: 分别切换账号、服务器、媒体库和排序方式，并在清理缓存或调整图片缓存设置后再次访问已有内容，检查展示结果及重新加载行为。

**Acceptance Scenarios**:

1. **Given** 某账号的某个媒体库已加载，**When** 用户切换账号、服务器、认证身份、媒体库或排序方式，**Then** 应用不得复用不匹配的列表作为新上下文的结果。
2. **Given** 数据缓存已关闭，**When** 用户返回电影列表，**Then** 应用按现有加载流程获取列表，不使用本功能保存的列表快照。
3. **Given** 已保存列表快照，**When** 用户清理数据缓存后再次打开该列表，**Then** 已清理的列表快照不再被复用。
4. **Given** 已取得海报的本地缓存地址，**When** 用户清空图片缓存或更改图片缓存开关、分辨率或容量设置后再次访问，**Then** 应用重新按当前设置处理图片，不依赖之前记住的本地地址。
5. **Given** 某次图片缓存处理仍在进行，**When** 缓存已清理或图片缓存设置已变化后旧处理才完成，**Then** 旧处理结果不得重新建立已失效的图片地址复用记录。

---

### User Story 5 - 缓存图片失效后自动恢复 (Priority: P2)

作为持续浏览大量电影的用户，我希望缓存容量不足或本地文件失效时，应用仍能显示可用海报，并优先保留最近实际浏览过的图片。

**Why this priority**: 图片地址复用不能使已淘汰的文件长期造成空白海报，也不能使常用图片被误判为长期未使用。

**Independent Test**: 删除已展示海报的本地文件，检查服务器回退及下次访问恢复；另在容量仅能容纳两张图片时依次加载三张图片，检查最近重新浏览的图片是否被保留。

**Acceptance Scenarios**:

1. **Given** 卡片记住的本地海报文件已被淘汰或损坏，**When** 本地海报加载失败，**Then** 应用使该地址的复用记录失效，并先尝试同一张海报的服务器地址。
2. **Given** 本地海报及同一图片的服务器地址均不可用，**When** 图片仍加载失败，**Then** 应用依次尝试已有备用图片；全部失败后展示占位内容，不无限重试。
3. **Given** 某次本地地址已失效，**When** 用户再次访问该图片，**Then** 应用重新进行缓存处理，有机会恢复正常海报。
4. **Given** 容量只能容纳两张等大小图片，图片 A 比 B 更早加入缓存，但最近又被实际读取，**When** 图片 C 加入并触发淘汰，**Then** 保留 A 和 C，淘汰最近未使用的 B。

### Edge Cases

- 已加载结果为空：空列表也属于有效列表快照，返回时可直接展示空结果并后台刷新。
- 缓存已被淘汰或从未建立：正常执行首次加载，不假定所有返回操作都一定命中缓存。
- 后台刷新导致某张海报来源变化：加载新图片，其他未变化的海报继续显示。
- 快速切换媒体库、账号或排序：较早请求的完成结果不得覆盖当前上下文。
- 缓存处理中离开页面：完成结果不得更新已离开的页面；仍有效的共享处理结果可供后续访问使用。
- 图片地址回退到服务器：回退属于可恢复状态，下次访问继续尝试本地缓存。
- 图片缓存未启用或不可用：沿用服务器图片及既有备用图片、占位内容逻辑。
- 清理缓存时仍有旧图片处理进行：旧结果不能恢复已失效的地址复用记录。
- 缓存容量不足：保留容量限制及淘汰能力，复用记录不得无限增长；有效图片读取的访问记录更新失败时，不得使已读到的图片无法展示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 数据缓存启用且当前浏览上下文存在有效列表快照时，系统 MUST 在返回列表后的首个列表内容画面展示快照，不等待本次网络刷新，也不先显示整页加载提示。
- **FR-002**: 复用列表后，系统 MUST 在后台刷新数据；刷新成功后更新列表，刷新失败时保留已有列表并提示正在展示保存内容。
- **FR-003**: 后台刷新期间，列表 MUST 保持可浏览和可打开详情；对于电影和图片内容未变化的卡片，刷新完成 MUST NOT 造成海报清空或再次加载。
- **FR-004**: 列表快照 MUST 匹配服务器、账号与认证身份、媒体库和排序方式；不匹配的快照及过时请求结果 MUST NOT 被展示为当前上下文的内容。
- **FR-005**: 图片缓存可用时，系统 MUST 先确定可用图片来源再开始卡片图片展示，避免在本地缓存处理完成前额外加载服务器图片。
- **FR-006**: 对已成功取得且仍有效的本地图片地址，系统 MUST 支持同一应用运行期间的直接复用；同一来源的并发图片处理 MUST 共享结果，避免重复下载。
- **FR-007**: 图片来源切换时，系统 MUST 避免将上一张图片显示为新内容；缓存处理失败或服务器地址回退 MUST NOT 永久阻止下一次本地缓存尝试。
- **FR-008**: 清理图片缓存或更改图片缓存开关、分辨率、容量设置后，系统 MUST 使记住的图片地址失效，后续访问按当前设置处理；已经失效的旧处理结果 MUST NOT 恢复地址复用记录。
- **FR-009**: 已复用的本地图片加载失败时，系统 MUST 使对应地址复用记录失效，优先回退到同一图片的服务器地址；失败后继续使用已有备用图片和占位内容规则，且不得无限重试。
- **FR-010**: 缓存中的图片被实际读取时，系统 MUST 将其计为最近使用；容量超限时，系统 MUST 按最近使用情况淘汰图片，不能仅因没有再次执行首次缓存处理就将常用图片视为未访问。
- **FR-011**: 数据缓存关闭时，系统 MUST 停止保存和复用本功能的列表快照；清理数据缓存 MUST 同时清理本功能已有的列表快照。
- **FR-012**: 列表快照与图片地址复用记录 MUST 有容量边界；缓存缺失或记录被淘汰时 MUST 允许恢复正常加载。
- **FR-013**: 图片地址复用、共享加载及失效恢复 MUST 覆盖使用同一图片卡片行为的电影列表、首页媒体卡片、媒体库封面、聚合视图及搜索结果；本功能新增的列表快照复用仅针对媒体库项目列表。
- **FR-014**: 本功能 MUST 保持现有排序、电影详情导航、图片备用来源、缓存设置入口及播放行为；不新增用户必须手动执行的预加载操作。

### Key Entities *(include if feature involves data)*

- **浏览上下文**：确定当前列表属于谁及如何排列，包括服务器、账号与认证身份、媒体库、排序方式和当前应用运行范围。
- **列表快照**：某一浏览上下文最近成功加载的电影结果，包括空结果；用于立即恢复列表，可被成功刷新替换或被缓存管理操作清理。
- **图片来源与复用记录**：原始海报来源及对应的可用本地图片地址；仅有效本地地址可复用，失效后应允许重新处理。
- **共享图片加载**：同一图片来源尚未完成的一次处理，以及等待该结果的多个卡片。
- **缓存使用记录**：图片最近被使用的时间，用于容量超限时决定淘汰顺序。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在列表及图片缓存仍有效、相关缓存设置启用的条件下，连续执行 10 次“打开电影详情—返回同一列表”，即使每次列表刷新延迟 3 秒，10 次返回均在首个列表内容画面展示已有列表，不出现整页加载提示，也不重新下载内容未变的已缓存海报。
- **SC-002**: 返回后后台刷新提供相同电影和海报内容时，已有海报清空或重新加载的次数为 0；刷新失败时，列表仍可浏览且显示保存内容提示。
- **SC-003**: 同时展示 3 张引用相同未缓存图片的卡片时，同一来源的图片下载次数最多为 1；本地缓存处理尚未完成时，额外服务器图片加载次数为 0。
- **SC-004**: 在服务器、账号与认证身份、媒体库及排序方式的切换验收中，错误复用其他上下文列表或被较早请求覆盖当前结果的次数为 0。
- **SC-005**: 清理数据缓存、清理图片缓存，以及图片缓存开关、分辨率和容量调整后的后续访问，均遵循当前设置；旧处理完成后恢复已失效图片地址记录的次数为 0。
- **SC-006**: 本地海报文件不可用但服务器图片可用时，卡片能够恢复同一海报；所有来源均不可用时，最终显示占位内容且不无限重试；下次访问会重新尝试缓存处理。
- **SC-007**: 在仅能容纳两张等大小图片的缓存中，按“A 加入、B 加入、A 被再次实际读取、C 加入”的顺序操作，最终保留 A 与 C，淘汰 B。

## Assumptions

- 本规格补写已完成修改的预期行为；质量检查通过不等于真实客户端显示效果已验收通过。
- “立即展示”指无需等待本次网络刷新即可在首个列表内容画面显示已有内容，不承诺特定设备上的毫秒级耗时。
- “有效缓存”指与当前上下文匹配、尚未被清理或淘汰且对应内容仍可使用的缓存；不保证永远命中。
- 列表复用范围是同一应用运行期间的媒体库项目列表，不新增跨重启的列表快照保存要求；既有图片缓存持久化能力继续沿用。
- 本次图片加载调整针对现有图片卡片，不要求重做详情页大图、人物图片或播放器选集缩略图的全部加载策略。
- 不新增滚动位置恢复、分页、列表虚拟化、新缓存设置项或界面重设计要求。
- 依赖现有身份认证、列表获取、图片缓存、容量管理和设置保存能力；无法获取新内容时，依照已有缓存是否可用分别采用保留内容或失败提示。
