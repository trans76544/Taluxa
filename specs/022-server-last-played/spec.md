# Feature Specification: Server Last Played Time

**Feature Branch**: `022-server-last-played`

**Created**: 2026-09-27

**Status**: Draft

**Input**: User description: "我希望将这里的每个emby服务器的添加时间改为最近一次播放过的时间"。截图指向侧栏“服务器”列表中账户名称下方当前标为“登录过”的日期。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - See the latest playback date (Priority: P1)

用户查看侧栏服务器列表时，希望每条服务器账户下方显示最近一次在本应用中实际播放媒体的日期，以便快速判断自己上次使用该账户观看内容的时间。

**Why this priority**: 这是截图所指位置的核心改动，避免把登录或添加日期误认为观看日期。

**Independent Test**: 以一个已保存账户成功开始播放电影或剧集，然后查看该账户在服务器列表中的日期和文案；无需进行其他操作即可验证。

**Acceptance Scenarios**:

1. **Given** 一个账户已有较早的播放记录，**When** 该账户成功开始播放另一部媒体，**Then** 该行显示本次播放开始的本地日期，并标为“播放过”。
2. **Given** 一个账户的登录日期晚于其最后播放日期，**When** 用户查看服务器列表，**Then** 显示最后播放日期，不显示登录日期作为播放日期。
3. **Given** 用户仅打开媒体详情或发起播放但媒体未实际开始，**When** 用户查看服务器列表，**Then** 最近播放日期保持不变。

---

### User Story 2 - Keep each account's history separate (Priority: P2)

用户在多个 Emby 服务器或同一服务器的多个账户之间切换时，希望每一行保留自己的最近播放日期，重启应用后也能继续看到正确结果。

**Why this priority**: 侧栏同时展示多个已保存账户，错误地共用日期会让信息失去意义。

**Independent Test**: 分别在两个已保存账户下播放媒体，重启应用并切换账户，核对两行日期各自对应其最后一次播放。

**Acceptance Scenarios**:

1. **Given** 账户 A 和账户 B 均已保存，**When** 仅账户 A 开始播放，**Then** 只有账户 A 的最近播放日期更新。
2. **Given** 同一服务器下保存了两个不同账户，**When** 其中一个账户开始播放，**Then** 另一个账户的最近播放日期不变。
3. **Given** 某账户已有最近播放日期，**When** 用户重启应用或切换当前账户，**Then** 该账户仍显示其最近一次播放日期。

---

### User Story 3 - Recognize accounts without playback (Priority: P3)

用户新增服务器账户，或升级后现有账户尚无可用播放时间时，希望界面清楚表明没有播放记录，而不是把其他日期标成播放时间。

**Why this priority**: 未播放状态是新功能的正常起点，必须与真实观看记录区分。

**Independent Test**: 新增一个账户但不播放媒体，查看其侧栏文字；随后成功开始播放并确认占位文字被日期替换。

**Acceptance Scenarios**:

1. **Given** 一个账户没有可用的最近播放记录，**When** 它出现在服务器列表，**Then** 用户名仍显示，日期位置显示“暂无播放记录”。
2. **Given** 一个账户显示“暂无播放记录”，**When** 该账户成功开始播放媒体，**Then** 占位文字变为本次播放日期和“播放过”标识。

### Edge Cases

- 已保存的旧账户没有最近播放记录时，登录时间或账户添加时间不能被当成播放时间。
- 播放源解析失败、播放器启动失败，或媒体从未真正开始播放时，不更新日期。
- 多个播放器窗口或快速切换媒体产生先后交错的播放事件时，较早的播放不能覆盖较新的记录。
- 播放发生在未选中的已保存账户下时，仍应更新实际播放账户对应的行。
- 更改服务器备注、登录账户或切换当前账户时，不应改变最近播放日期。
- 删除账户后，该账户的播放日期不应显示在其他账户行中。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 服务器列表中每条已保存账户记录 MUST 显示该账户在本应用中最近一次实际开始播放媒体的日期，而不是账户添加时间或最近登录时间。
- **FR-002**: 最近播放时间 MUST 在媒体实际开始播放时更新；浏览内容、准备播放以及失败的启动尝试 MUST NOT 更新该时间。
- **FR-003**: 电影、剧集及本应用现有的其他可播放媒体 MUST 遵循相同的最近播放时间规则。
- **FR-004**: 每次新的实际播放 MUST 只更新对应服务器和账户的记录；相同服务器下的其他账户和其他服务器账户 MUST 保持不变。
- **FR-005**: 对同一账户，较早的播放事件 MUST NOT 覆盖较新的最近播放时间。
- **FR-006**: 最近播放时间 MUST 在应用重启和当前账户切换后保留。
- **FR-007**: 有最近播放时间的行 MUST 显示用户本地日历日期和“播放过”标识，并保留现有用户名。
- **FR-008**: 没有可用最近播放时间的行 MUST 显示“暂无播放记录”，且 MUST NOT 使用登录时间或添加时间充当播放时间。
- **FR-009**: 实际播放开始后，当前可见的服务器列表 MUST 自动显示更新后的日期，无需用户重启应用或重新登录。
- **FR-010**: 本功能 MUST 保持现有服务器列表顺序、账户选择和服务器备注行为不变。

### Key Entities

- **已保存服务器账户**：侧栏中的一条记录，由服务器和登录账户共同确定，包含显示名称及其最近播放时间。
- **播放开始**：某个已保存服务器账户下的媒体实际进入播放状态的时刻；是最近播放时间更新的依据。
- **最近播放时间**：该账户最近一次有效播放开始的时间；界面显示其本地日历日期。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在电影、剧集及其他现有可播放媒体的验证场景中，100% 的成功播放会在开始后 2 秒内更新对应可见账户行的日期。
- **SC-002**: 在失败启动、仅浏览和仅登录的验证场景中，错误更新最近播放日期的次数为 0。
- **SC-003**: 在跨服务器、同服务器多账户和多个播放器窗口的验证场景中，100% 的播放只改变所属账户的最近播放记录，且旧事件不会覆盖新日期。
- **SC-004**: 在应用重启和账户切换的验证场景中，100% 的已有最近播放日期仍与重启或切换前一致。
- **SC-005**: 在无播放记录的验证场景中，100% 的账户行显示“暂无播放记录”，不显示误标为播放时间的其他日期。

## Assumptions

- “这里”指截图中的侧栏“服务器”列表；其中一行代表一个已保存的服务器账户，即使多个账户连接同一服务器也分别显示。
- “最近一次播放”指用户通过本桌面应用实际开始播放媒体的时间；其他客户端或 Emby 服务器既有的历史播放记录不在本次范围内。
- 升级前没有可识别的账户级播放时间时，不从登录日期、添加日期或媒体列表推算历史播放时间。
- 日期沿用应用当前的本地日期展示习惯；记录保留完整时间，以便正确识别哪一次播放更新。
- 本功能仅改变该行的时间含义和提示文字，不要求按播放时间重新排列服务器列表。
